# Concern 11.9 User Experience — worked example & design rationale (non-normative)

> Migrated from the Dictum standard's `concerns/11.9-user-experience.md` in the 2026-07
> compaction audit. The standard states the rules; this holds the illustrative
> worked example and the design-decision rationale/evidence behind them.
> Describe-by-shape; non-normative — where this and the standard disagree, the
> standard wins.

## Worked example (a planning SaaS)

`13-tenant-ux.md` / `12-platform-admin-ux.md` / `16-views.md` — where missing-frontend, dead-links, orphan-screens, and missing-states failures concentrated. At *Contract-grade*:
- **`SCREEN-GRID-VIEW`:** route `/models/:id/views/:viewId`; sidebar entry under the model; guarded by `ROLE-MODEL-CONTRIBUTOR`; realizes `CAP-VIEW-GRID`; calls `API-VIEW-SAVE`; states = loading grid / empty "no assets" / per-cell save error; in `JOURNEY-CONTRIB-ENTRY` (Login → Dashboard → Model → View List → Grid).
- **Navigation contract:** every screen reachable, every link resolves to an existing screen.
- **Component-reuse rule:** reuse the shared Angular component library; no bespoke styles. `[REVISIT]` for the design-tool binding — blocked-by-environment: no consumable design tool is in play; re-entry condition = one is.

## Design decisions & rationale

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | UX owns a navigation *contract*, not navigation prose. | Making route + menu + guard + reachability a deliverable is what prevents orphan screens and dead links — the failure where nav was described but never built. |
| 2 | `SCREEN-###` binds `CAP` + **the interface surface it drives** + a guard (`ROLE` where auth exists, else the enabling condition). | The screen is the UI-side integration point; binding it to its backing surface + guard makes single-layer "done" impossible in either direction. Generalized from `CAP + API + ROLE`: a client-only product has no `API-###` and may have no auth surface, but the screen still drives *some* contracted surface (`LIB-###`/input bindings) and still has a stated guard — "enabling condition" keeps the slot filled instead of vacuous. |
| 3 | The component-reuse rule **is** the rule; design-tool binding is `[REVISIT]` as **blocked-by-environment**, not a standing design gap. | Design-tool unavailability is an instance of the Part 10a blocked-by-environment mechanism, applied to an authoring input: the binding environment (a consumable design system/tool) is structurally unavailable, so the refinement carries a recorded marker with cause (no design tool), scope (the design-tool binding of this sub-aspect), and re-entry condition (a design tool is actually in play) — not an open topic on a parked list. Until then the component-reuse rule keeps the surface consistent; when the condition fires, the topic re-enters as ordinary demand through the enhancement lifecycle (10d). |
| 4 | Contract-grade requires loading/empty/error states + journey placement. | These are exactly what was missing when features shipped happy-path-only; mandating them ties UX completeness to the real failure modes. |
| 5 | A live/event-driven UI must also spec event-driven/ambient states (connection/presence/typing/unread/`EVT-S-ERROR`). | #16 hardened the bar around *click-driven* controls; a live product's load-bearing states are **push/ambient** and the user never clicks them, so they'd pass the click-centric bar while absent (failure-mode #17). This is the event-surface analogue of #16: #16 made the bar operate every click-driven control; a live UI's defects hide in the push/ambient states the user never clicks. |
| 6 | Bless the SPA-shell pattern; `ROUTE-###`↔`SCREEN-###` is N:1. | A real SPA is one persistent shell with panel/modal screens layered over it; forcing "one screen = one page" fought the actual product. A panel is still a `SCREEN-###` with the full contract, still deep-linkable and reachability-checked — so no-orphans holds without page-shaped screens. |
| 7 | `ROUTE-###` is conditional on a URL surface; routeless products bind navigation to an owned state-machine register. | A pointer-locked canvas product has app states, not URLs — minting `ROUTE-###` there is the spurious-prefix anti-pattern. The reachability *intent* survives the generalization: every screen reachable via a spec'd transition, every transition resolving to a real screen. |
| 8 | The ambient bar triggers on **any non-user-action state change**; server push is one instance. | The earlier bar named only server-pushed `EVT-###` states, so a client-only product's timers, lock-loss pauses, and worker-completion states — the exact failure-mode-#17 class — read as out of the bar's reach. The trigger is the *provenance* of the state change (not a user action), not the transport (failure-mode #22). |
| 9 | A **layer** is a third screen kind; its reachability fact is its toggle/trigger. | Debug overlays, toasts, and banners fit neither page nor panel, leaving the no-orphans rule undefined for them — and an unclassified surface is an unchecked one. Tying reachability to the trigger keeps the register total. |
| 10 | **Bar tightening:** modal inertness is **input-channel-complete** (pointer AND keyboard); 11.14 owns only focus-order refinement. | A modal whose scrim blocked pointer input was Tab-bypassable; the defect surfaced as exactly that — a Tab-bypass of a click-blocking scrim, caught only because a11y happened to be in scope, and with 11.14 scoped out it would have shipped. Background interaction through any input channel is a UX correctness bug — splitting it by channel had parked half the bug in an optional concern (failure-mode #20). |
| 11 | The component-reuse rule defaults out when no component library exists. | The rule presumed a shared library; for a zero-dependency hand-rolled UI it was meaningless as written. What survives is the in-product visual-consistency obligation, owned by the screen specs themselves. |
